# Main stock-binding preflight, without activation

A new internal POSIX preflight requires exact package metadata and both native
supplier source files from the authenticated stock acquisition. Dependencies,
peers, loader declarations, hooks, engines and unknown metadata cannot silently
change. This deliberately preserves the existing byte-exact metadata contract.

## Production boundary

`userVerifyMainBindings` compares the entire private source to the caller-bound
retained snapshot before and after the ordinary owned process. The helper's
`verify-main-source` action runs every existing stock graph, source, supplier,
native-state, settings and lock check. It then compares the three fixed bindings.
Only modern Separate is admitted; stock `verify` remains unchanged. The new
module is an embedded, custody-checked provision asset. Neither path loads Main,
writes settings, replaces the prefix, nor claims API/runtime qualification.

## Evidence

The established offline credentialless Linux Guest authenticates Gentle Pi 4.0.0
against the committed npm SRI and checks both existing supplier hashes. It creates
private retained ZIP DATA and materializes it through the production consumer.
The actual comparator accepts unchanged bindings plus a changed README, and
refuses dependency/export/Pi/engine/hook/unknown declarations and either changed
supplier. Readback verifies unchanged bytes/stat and exact source custody.

Two supplier changes produced genuine behavioral REDs before comparison was
added. The first regression's old four-asset assertion failed after adding the
fifth asset; that stale inventory control is not behavioral RED. ZIP DATA and Node comparator execution are not TLS-acquisition,
full-helper/process qualification, native Darwin/Windows installation or launch
evidence. The stock supervisor-custody prerequisite remains unresolved.
