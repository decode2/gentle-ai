## Test design (source added; native ACL proof not established)

1. `newOwnerACLFixture(t)` creates a unique disposable `/private/tmp` parent and held empty `0600` child. `proveOwnerACLReplacement(t, file, path, before)` must pass **before** any child payload. A's inode check requires size zero, so never call it on the child after writing. Do not use a real private destination. Write a fixed benign synthetic marker only to that held child, verify full write, sync/close as appropriate, and check owner can reopen/read the exact marker. Keep cleanup of the disposable parent even on failure.
2. Before lowering parent mode to `0711`, create a separate benign canary/control file under the same parent, with owner/readable permissions verified, then chmod parent `0711` and verify mode. The parent ACL may still have its inherited `everyone` setup; this is an experiment in **child** denial, not parent confidentiality. The probe must open the canary through the same parent path and demonstrate ancestor traversal and readable control data; it must also successfully stat the child pathname as a precondition to the read attempt. If traversal, canary read or child pathname stat fails, child denial is inconclusive and the test **fails**.
3. Before sudo, run `/usr/bin/id -u _nobody` with direct argv. A failed lookup, including exit 1, is `account-lookup-failed` plus its numeric exit code; it does not prove the account is absent. Use `executable-unavailable` only when Go reports a concrete executable-not-found/permission error. Do not expose raw output or account data. Require passwordless `sudo -n -u _nobody` on native macOS (no prompts). On failed identity execution, report only `sudo-command-failed` plus numeric exit, except for a concrete Go executable-not-found/permission error, which is `executable-unavailable`. Use `Output()` so sudo stderr is discarded; never infer causes from diagnostic text or print raw output, paths, or account data. Invalid successful identity output is a safe failure with a numeric status. Verify probe's actual effective UID via the same execution path, distinct from child owner and nonzero; do not infer identity from the username. Use direct `exec.Command` arguments, never interpolate an untrusted pathname into shell code; if a fixed helper is required, pass paths as separate arguments. For each of `read` (`O_RDONLY`) and `write` (`O_WRONLY`), run a distinct real `sudo -n -u _nobody` child with the mode passed as a direct argv value. Each child must verify actual UID, read the same-parent canary, and stat the child pathname before opening; it must return the classified `EACCES`/`EPERM` denial, not just a missing file or nonzero exit. Neither attempt may include `O_TRUNC`/`O_CREAT` or read/write the protected FD. The parent separately requires the exact denial exit code and **empty stdout and stderr** for both children. For probe failures, report only the fixed mode, numeric status, and stdout/stderr lengths; never print raw output, errors, or paths. Do not print the marker or count test-harness diagnostics as file data. Any successful child open, different errno, probe failure, unavailable sudo, same/root UID, or missing canary proof is FAIL/BLOCK, never SKIP or fallback owner-only success. No `testing.Short()` escape for this required native proof.
4. Capture exact native fork `workflow_dispatch` SHA/run URL, selector listing, A and B focused outputs, exit codes, and independent review disposition. A's green is a prerequisite, not B's result. Linux tagged tests exclude Darwin/cgo and cannot prove this behavior. A native failure or inconclusive probe is BLOCK, not GREEN. Never reuse actual user data.

## Key Learnings

- Same-FD owner ACE replacement is narrower than proof that a distinct principal cannot read a child pathname.
- A denial without actual distinct UID and a readable same-parent control is inconclusive; missing sudo must fail closed.
- Selector registration RED precedes test source GREEN; source GREEN remains unobserved. Unique probe exit codes separate readable canary, stat, identity, successful open and unexpected errno from EACCES/EPERM for each open mode, without treating test-harness output as data. Only synthetic markers are permitted, and neither proof changes production refusal.
