# Darwin private-file ACL experiment

## Goal and authority
At canonical parent draft PR [#4936](https://github.com/Gentleman-Programming/gentle-ai/pull/4936), head `9442ab6f`, determine on **native macOS** whether `acl_set_fd_np` with an empty extended ACL removes a permissive ACE inherited by a held, newly created `O_EXCL` empty inode, and what descriptor-bound readback reports. This is a test-only experiment, not a Darwin report writer or permission to enable one. This worktree is dedicated to the experiment. This request authorizes only the native registration RED milestone: workflow and tracker edits, local checks, and one local commit. No source/test/helper, push, or PR in this step.

## Key Learnings
- Parent #4936 proves Linux private writing and native Darwin/Windows **refusal**, not Darwin ACL safety. `report_unsupported.go` currently covers every non-Linux platform.
- Cross-compilation or a skipped/nonowner-unavailable test cannot prove macOS inherited-ACL clearing; real inheritance and descriptor-bound post-set inspection on native macOS are necessary.
- The registration step deliberately goes RED on native macOS until the build-tagged test exists; Linux checks cannot stand in for the native observation. No source edits or native ACL result exist yet.
