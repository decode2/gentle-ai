# Keep the Gentle-Shell request portable

The user installer keeps one request and entry protocol while isolating native execution helpers. This is a behavior-preserving Linux preparation unit, not a macOS or Windows installer.

## Source boundaries

| Source | Responsibility |
|---|---|
| `internal/shellinstaller/user_install.go` | Request/result, manifest, confirmation, entry parsing and repair advice |
| `internal/shellinstaller/user_manager_args_linux.go` | Existing systemd-user argv and setpriv capability-clearing helper |
| `internal/shellinstaller/user_binding_posix.go` | Existing literal POSIX launcher binding generation, built for Linux and Darwin |
| `internal/shellinstaller/user_install_linux.go` | Linux physical inspection and execution |
| `internal/shellinstaller/user_install_unsupported.go` | Existing explicit unsupported behavior outside Linux |

The POSIX binding tests retain Linux and Darwin coverage. Windows never executes these shell bindings; native Windows bindings remain future implementation work.

## Verification boundary

Portable entry tests parse literal POSIX/Windows path strings and Shared/Separate selections through the unchanged five-argument entry. They do not validate those paths or authorize installation. Confirmation tests preserve selection and physical-identity sensitivity without binding prior approval into the digest. Physical selection and execution still belong to the platform implementation.

Linux tests continue to exercise real POSIX quoting and manager argv without changing generated bytes. Target-source selection and Darwin/Windows cross-compilation verify separation and type compatibility only. Native permissions, process termination, installation, launch, update and recovery on those systems still require native evidence.

## Delivery dependency

This unit builds on PR #5242's published Linux source boundary, before unpublished UI/preferences work. It can be reviewed as a focused child diff without dragging in the local UI prototype. It does not close the Linux MVP issue or the separate cross-platform route/diagnostics issue, and introduces no preference schema or additional entry argument.
